- Naming: `{Name}Entity`, `I{Action}UseCase` + `{Action}UseCase`, `I{Aggregate}Repository` + `{Aggregate}Repository`, `I{Domain}QueryService` + `{Domain}QueryService`, `{Feature}Endpoints` static class with `Map{Feature}Endpoints` extension.
- DI lifetime: Scoped throughout. No singletons except framework `IOptions`.
- Spanish "Infraestructure" spelling intentional — match it everywhere.
- Use case interfaces live under `Domain/Application/{Feature}/`, NOT in the Application project.
- Domain entities are POCOs (public getters/setters). Behavior in use cases. `Money`, `Currency`, `Isin` remain rich VOs.
- `Money` is `(decimal Amount, Currency Currency)`. Adding mismatched currencies throws. Never bare `decimal` for money.

- ISIN is the primary instrument identity. Tickers keyed by `(isin, exchange)`.
- Multi-tenancy: every user-owned entity carries `AccountId`. Repos filter by `AccountId` on every query. Query services post-validate via `AccountGuard.EnforceSingle/EnforceMany`. Two layers of defense — never rely on API-level filtering alone.
- P&L always reports three faces: native, account, FX attribution.
